# 评测工坊

用真实项目题目比较自己的模型，从选定任务片段建立私人题库，导出单文件成绩网页。

## 发布状态

首次发布候选版本保持 **1.0.0**。依赖配套 Cindy 的模型目录、下载、任务/团队及委派 Auto 上下文接口；尚未在正式/Beta 发布版完成验证。现有 manifest 最低版本 `0.1.93` 只是待确认声明，**不代表该版本已支持这些接口**；合入前必须确定实际最低版本并完成真实安装包验收。初始 provisioning 为定向空受众，不自动安装给任何用户。接口缺失时显示升级/错误提示，不退回付费模型探测。

## 使用

1. 打开主页面。自动分配保存位置，无需先选择目录。
2. 选择题库、模型和思考强度，开始测试。默认模型可见性跟随 Cindy 模型选择器。
3. 一个主任务协调多个 Orca Worker 并行作答，高级设置可限制并发。所有动作仍走宿主 Auto 审批；插件不能授予 Full access 或冒充用户原话。
4. 进度自动更新，准备与运行阶段均可停止。执行状态不确定时核对回执，不盲目重派、不算零分。
5. 历史成绩默认按每题最近一次有效成绩汇总模型配置；平均模式先按题平均再合计。版本与内容哈希不同的成绩不混算。可以导出当前榜单或指定结果。

主任务和 Worker 都可能产生所选账号的模型费用。只展示已知美元金额，未知不记零。耗时是观测到的执行窗口，不代表纯计算时间。Worker 报告自身不构成交卷证据，插件先核对宿主任务/团队状态再评分；回执不是密码学认证。

模型派发前，准备流程检查插件 Node 进程环境能否运行 `python3`；这只检查运行前提，不代表所有评分依赖均已安装。协调计划和状态文件放在宿主主任务目录。不迁移未发布开发版放在数据目录的旧计划，原文件保留。当前批次重载复用原冻结计划，包括发送回执保存后、调度进度保存前中断的情况。

恢复模型派发或评分前执行同一 Python 预检；宿主回执核对和已保存成绩的结算不依赖此预检。解释器不可用时，未评分作答留给现有恢复流程，不重放模型作答。未发布开发版的单题批次只观察、评分或停止已被受理的作答，不再创建、准备、升权或派发新作答。丢失回执只读找回，有歧义则拒绝；停止旧批次后可新建主任务批次，原答案与报告保留。出题/校准期间（包括独立草稿、校准和冻结调用），以及失败出题任务仍保留可恢复执行时，禁止更换数据目录；校准报告明确通过或用户明确结束且确认无运行/未知执行后才解除占用；未通过的报告保留为失败状态，可修正后显式重试。目录选择返回后保存前再次核对。独立草稿也先在现有 author 记录保存身份再写文件，工具返回和重载后继续绑定目录；丢回包保留同一身份，确定材料缺失可重新选择。所选原文仍只存选定目录，不进入配置记录。

## 题库与本地执行

默认来源为 [makecindy/eval-bank](https://github.com/makecindy/eval-bank) 的[固定 Release](https://github.com/makecindy/eval-bank/releases/tag/eval-bank-20260925)。七类题包括音频、灵动岛、自动恢复、输入框发送、手机历史顺序、远程文件和消息投影缓存。每题1分，按冻结考核权重计算；未测齐与环境无效单列。

按需下载选定题目及运行环境，校验字节数、哈希和解包路径后才启用。旧版本可以离线继续使用，更新不覆盖进行中的作答。默认运行环境目前要求 **macOS Apple Silicon 和 Python 3**。不支持的平台在请求题包下载及安装前拒绝，仍可浏览目录。大型题库放在 GitHub Release，不塞进插件。

评分和校准会以本机用户权限**执行题包提供的本地代码**，也可能执行候选程序。首版仅面向可信题库：官方题库由维护者提供并审核；其他题库由用户自行发起生成并使用，或由维护者审核。用户发起的出题流程包含自动校准，不另设生成后的人工审批。生成与校准不等于安全审查，不用于执行来源不明或不受信任的题包。本版不增加系统沙箱或宿主隔离接口。哈希只证明完整性，不证明安全；评分器/参考答案与作答目录分离不等于系统沙箱。

题库 `distribution.json` 与题目 `question.json` 元数据各限 16 MiB，解析前采用有限字节读取。题库相对路径在所有平台统一使用正斜杠，拒绝反斜杠；元数据上限不改变已批准的归档与展开容量。 在线索引下载内容与保存后的 `{url,index}` 缓存包装分别限 16 MiB；接近上限的源索引须为包装预留空间才能发布缓存。

## 私人题库与隐私

只处理用户粘贴或明确选择的任务片段，不扫描全部历史。交给出题模型前请移除凭证和私人信息。草稿包含产品合同、候选项目、参考答案、独立评分器和不完整对照；通过校准后由用户冻结为新版本。校准只是机械门槛，不能替代产品语义审阅和变异检查。

作答、快照、诊断和草稿留在本地，Library 保存设置与导出网页。公开报告不包含原始诊断、聊天、源码或本机路径。分享只导出文件，不自动托管上线。卸载不删除 Library 或外部评测目录。

校准按候选、参考答案、不完整对照分成三个有独立时限的请求。草稿快照确定稳定的校准编号，响应丢失后仍可找回。已完成步骤复用回执；执行结果未知的中断步骤不自动重跑。草稿变化会使校准失效。完成报告是重试与结束出题的依据，不再重复审核已归档的逐步回执。已结束且未通过的报告可通过“重新校准”建立新尝试，旧报告保留；同一重试请求丢回包后找回同一次尝试。明确结束出题会保存旧身份，旧题目标识与版本不再复用。

准备作答前先保存身份，文件完整后独占发布；恢复仅补齐与原题一致的内容，用户改动与未知文件保留。评分由实际执行评分程序的 Python 进程持有系统文件锁；进程仍在运行时不重复评分，退出后锁由系统释放。评分中断且没有完整回执时，恢复评测只对已保存的答案重新做本地评分，不重新调用模型；完整回执直接恢复正式结果。每次未完成的评分快照单独保留，不覆盖付费作答目录，也不自动清理，可能额外占用磁盘空间。冻结清单由持有系统文件锁的 Python 写入进程发布，中断后锁由系统释放，同版本重复冻结核对内容后返回原结果。未发布开发版的 `freeze.lock`、`grading.lock` 和随机校准编号不作为当前执行门禁，原文件保留；不支持同时运行新旧开发版写入同一目录。

单项准备失败不阻断其他作答。计划内作答完成、团队空闲后，若剩余项均未准备，本批明确以遗漏项未运行、未计分结束，允许开始新评测。冻结计划不补入遗漏成员，已保存成绩不变。旧版部分批次可先停止，再对遗漏题目重新开始。

## 开发验证

出题时把选定材料复制到宿主任务自己的目录。宿主确认任务完成后，插件核验题目身份与普通文件内容，导回固定快照再校准。原始材料保留，任务后续改动不覆盖该快照。导回失败可在任务完成后使用既有 `calibrate_question` 入口重试交接。

损坏的在线题库先重新构建并校验，再替换；原题库保留在本地 `online/backups`。发布前校验失败或取消时原件不动，发布失败会尝试恢复原件。这不是跨进程事务或崩溃恢复保证，备份不自动删除，作答和成绩不变。

安装只保留 `online_begin` / `online_step` / `online_cancel` 一套实现；测试与本地资产验证脚本也借入归档文件、驱动同一路径。题包下载及下载缓存复用由宿主负责，插件自身仅获取小型索引。

- `node --test test/core.test.cjs test/bridge.test.cjs test/online.test.cjs test/defaults.test.cjs test/standings.test.cjs test/execution-quality.test.cjs test/task-scope.test.cjs test/engine.test.cjs`
- `EVAL_BROWSER_RUNTIME=<composer candidate/runtime> node --test test/view.test.cjs`
- 可选真实题库验证：`EVAL_TEST_BANK=<已还原题库> node --test test/engine.test.cjs`
- `python3 dev/build_online_bank.py <离线题库> <资产输出目录> <固定GitHub Release地址>`，资产输出放在本目录外。

浏览器测试使用宿主桥替身，不证明正式/Beta 实机兼容、真实供应商执行或全部重启/切账号行为。仓库 CI 生成 `.cindy` 验证包，发布前须记录安装与实机证据。不新增第三方 Node 内嵌依赖；题目与运行环境许可证随题库分发。

单题最多下载 **8 GiB 唯一归档**、累计展开 **32 GiB**；同一归档重复挂载时，展开大小逐层累计。旧题库与备份另占磁盘空间。安装分步复制、解压与校验，单次 Node 请求仍最多15分钟；一次安装会暂存最多8 GiB的归档副本，取消先停止解压再清理本次暂存。进程重启后的未知暂存不自动接管或删除。

保存目录必须支持硬链接；选择时以本次独立探针验证，不兼容时明确提示改选目录，不覆盖已有文件。

批次进度和导出报告跟随 Cindy 语言，使用简体中文或英文回退。题目名称、模型名称和外部诊断详情保持原文；分享报告仍不包含原始诊断。`prepare_run` 返回作答目录、prompt、授权范围及版本元数据，本身不运行模型。
