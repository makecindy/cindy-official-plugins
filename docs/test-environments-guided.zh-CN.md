# 1.2.0：从引导首页开始

> 当前 1.2.1 已进一步收成“选择项目 → 启动”，见[最简使用说明](test-environments-simple.zh-CN.md)。下文保留 1.2.0 的历史引导与证据。

[English](test-environments-guided.md)

旧首页把项目、账号、方案、用例和运行记录并排放在空白目录里，使用者不知道先做什么。
1.2.0 默认改为可操作的流程，原有目录管理收进“高级管理”；不改客户端/服务端。

## 本机只需这样开始

1. 选“本机”。首次只填项目名称和 Cindy 源码文件夹，点“保存项目并继续”。
   标识、持久隔离名、调试端口及默认开关由插件建立可复用配置；这一阶段不会启动。
   不知道源码位置时，可直接在 Cindy 对话里说：
   > 帮我找到本机的 Cindy 源码，配置测试环境，先预览不要启动。
   这里要的是源码，不是安装好的 Cindy.app，也不是本插件源码目录。
2. 选择已保存的项目及账号（首次先到目标应用正常登录），点击“检查启动设置”，
   核对电脑、项目、账号与数据档案后才点击“启动测试”。下次直接复用配置。
3. 首页按启动、选账号、准备样本、执行验收、停止显示状态及下一步。
   正式账号通过目标应用正常登录后被记住；密码与令牌不在插件页面填写。
4. 有 prepare/verify 才能直接执行脚本；没有脚本时给出让 Cindy 使用实际应用工具的说明。
   脚本完成不代替业务、真机或人工证据。普通 command 项目只显示进程启动，不冒充联网账号核验。
5. 停止前保存截图。停止会请求取消本次配置、从本次启动后产生的活动样本/验收命令和主实例，
   不影响另一项目。账号档案保留。历史、完整参数和诊断 JSON仍在高级管理。

## SSH 也在首页完成

1. 选“另一台电脑 · SSH”，填现有 SSH 电脑名，点“连接并读取项目”。Node 路径可在高级选项指定。
   B 需先有项目、配置、工具链和自己的正常登录；空白目录会明确给出准备说明。
2. 选 B 的配置，粘贴需要构建的**应用 PR 链接**，点击“读取 PR 并预览”。
   B 核对项目 origin 后，用固定 Git ls-remote 读取该 PR head，返回精确 SHA。
   无需手抄 SHA；需要指定旧版本时仍可在高级选项固定。读取失败不会启动。
3. 预览电脑、项目、版本后点击启动，继续准备/验收/停止/取证；原运行编号保留用于恢复。
   修改电脑或 PR 后旧启动按钮失效，需重新读取/预览，不会拿旧预览偷偷启动。
4. 回执丢失后保留同一个 runId，并提供“读取这次运行”，不留盲目重发启动的按钮。
   最近的远程运行可以恢复。脚本未配置、构建失败、未登录或结果未知均不能当作通过。
5. 截图在停止前取；停止后可取最终日志和结果。证据绑定当前 jobId/runId，不与另一运行混显。

浏览状态只保存经过校验的电脑名、目录引用、运行编号和不带查询参数的 PR URL。
无效 SSH 文本、PR 查询参数等不写入浏览器持久状态；不会保存 SSH 密码或私钥。

## 原来的五个入口是什么

| 高级入口 | 作用 |
| --- | --- |
| 项目 | 源码在哪里，用哪种接入方式和项目命令 |
| 启动方案 | 保存下次重复使用的账号选择、隔离数据与启动选项 |
| 账号 | 目标应用保存的公开账号引用与本机档案历史；不是密码库 |
| 用例 | 要检查的动作和预期，保存本身不执行测试 |
| 运行记录 | 启动、停止、失败和诊断历史 |

## 作者显示与测试边界

原来的 Chris 来自原始稿的固定 author 元数据，不是当前登录者的名字。
按使用者明确选择，1.2.0 省略 author，不填其他人、官方或匿名占位。Git 作者和已有贡献历史不变。
省略字段已通过 Forge 打包校验；宿主详情页排版由宿主决定，不能靠插件改写宿主界面。

引导页和高级管理复用同一目录/Worker/API；不扫描日常宿主的历史登录、不迁移或复制凭证。
本轮覆盖实际浏览器点击、旧高级功能回归、配置持久化、停止作用域、失联恢复、状态保存校验，
以及实际 Git/OpenSSH 回环。远程页面有显式测试适配，不能冒充真实双机或正式账号证据。
最终测试数量、源码提交与包哈希记录在 PR #309。
真实安装、正式账号、双机网络、真机/人工仍按[实机验收单](test-environments-acceptance.zh-CN.md)记录，
其中旧菜单操作可从高级管理进入。首次跨设备免密码授权仍未实现。
