# 1.3.0：选择账号，复用这台电脑的登录态

[English](test-environments-accounts.md)

当前按用户确认的范围**只改插件**，接受现有默认约 30 天的滑动续期机制。
本次不交付客户端、服务端、数据库改动，也不提供永久登录开关。

## 第一次怎么用

1. 在插件首页点“选择项目…”，用 Cindy 原生窗口选择 Cindy 源码项目。
2. “已保存的测试账号”先选“在测试应用中选择或添加账号”。
3. 在“首次登录使用的版本”选择国际版或中国大陆版，点“启动测试”。
4. 在打开的测试应用自己的登录页面完成登录。使用应用提供的企业 SSO、邮箱或手机号入口；插件不收密码、验证码、Cookie 或令牌。未开放的入口不能由插件补出来。
5. 回插件点“更新状态”。看到目标应用身份正确、状态通过联网核验后，继续准备样本和验收。
6. 要添加第二个账号，在测试应用自己的账号菜单中添加；完成后更新状态。不要退出第一个账号来代替添加账号。
7. 点“停止这次实例”。停止只结束本次进程，不删除应用登录档案。

## 下次怎么用

1. 选择要测试的源码项目（可以是另一个源码目录）。
2. 从“已保存的测试账号”选择甲或乙，再点“启动测试”。选择账号本身不会启动。
3. 插件使用该账号已保存的本机档案，应用负责切换身份和验证登录。有效时不需重新输入密码，失效则提示在应用里重新登录。
4. 一个档案同一时间只运行一个实例。先停止上一次，再拿它测试另一个项目。
5. 脚本准备样本/验收只在项目已配置时显示；没有脚本时按用例手工操作。启动成功不等于验收通过。

账号列表按应用给出的不透明账号标识保存，不按邮箱域名、手机号或个人 SSO 猜身份。
旧客户端不返回账号区域时，复用**上次登录档案使用的版本**，不要求升级客户端，也不猜账号区域。
同一个应用档案本身可保存多个账号；各自的会话仍由应用管理。

## 登录态在哪、能留多久

- 插件目录默认是 macOS 的 `~/Library/Application Support/Test Environments/catalog.json`，只存公开账号引用、配置与档案位置。
- 选中已保存账号后，展开首页“应用保管登录态的位置”，会显示该账号本机档案的真实路径。凭证由应用在该目录的 `safe-storage/` 中按现有机制保管；不要打开、复制或外发里面的文件。
- 默认约为最后一次成功续期后 30 天。正常使用、联网续期后继续往后延；准确期限以服务器配置为准，插件不更改期限。
- 停止后文件保留，但时间仍在走。某个账号长期未使用、退出或被撤销时可能需要重新登录；仅列在插件中不会在后台为它续期。
- 换电脑要在那台电脑自己的档案中登录。SSH 只控制和传输测试结果，不传凭证。

## 一步步验收

| 操作 | 预期 |
| --- | --- |
| 首次登录甲，更新状态 | 显示甲的实际身份；不能把“进程已运行”当“账号已验证” |
| 在应用里添加乙，更新状态后停止 | 下次启动的列表能选甲、乙；密码/验证码不进入插件 |
| 选甲启动，停止，再选乙启动 | 应用实际身份分别是甲、乙；有效会话无需重新输入密码 |
| 选另一源码目录，再选甲 | 复用甲原来的档案路径，而不是复制登录文件 |
| 旧版本没有 region 字段 | 仍可选账号，沿用已有档案版本，不要求主程序补接口 |
| 实例未停时复用同一档案启动 | 拒绝重复占用，不终止原实例 |
| 在应用中退出乙，再刷新 | 不把乙标为可直接复用，不自动切到甲来冒充乙登录成功 |
| 停止、关闭并重新打开插件 | 账号引用、原档案和配置仍在 |

真实账号的首次登录、SSO 组织确认、过期授权和双物理电脑仍需实机验收。自动测试使用占位身份，不证明这些项目通过。

## 本次不宣称实现

日常 Cindy 的已登录账号直接授权隔离测试实例、跨设备首次免输密码授权、任意现成桌面安装包的隔离启动，均不在本次插件改动中冒充支持。
浏览器 SSO 能否免输密码取决于浏览器/组织的现有会话。当前本机入口运行源码项目；现有 SSH 流程可以预览并检出目标应用 PR。
