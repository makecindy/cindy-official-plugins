# GitHub 可选 CI 恢复

GitHub 贡献者可能有权限推送自己的 PR 分支，却没有权限重跑失败的 Actions 任务。
反复出现的故障，根本仍应通过提高测试和 CI 稳定性解决。GitHub 插件另外提供有限的
恢复途径：确认是临时故障，且正常重跑明确因权限被拒后，才考虑重推。

在 PR 卡片右上角设置或 GitHub 插件设置页中，可以开启
**CI 无重跑权限时重推重试**。默认关闭，存量用户没有字段时也关闭。偏好保存在本机
当前插件用户的设置中，后续所有仓库和 PR 的实际跟进轮次共用，不同步到其他电脑。
可随时从任一入口关闭。此偏好不会自行启动自动跟进，也不授予合并权限。

现有 PR Skill 在新建跟进、每个实际后台轮次，以及 amend 和 push 前重新通过
`pr_follow_settings` 读取当前偏好。旧提示词或卡片返回不能作为长期重写授权。
字段缺失、关闭或读取失败都禁止仅为 CI 重试改写提交；正常且已授权的修复仍可继续。

恢复要求 PR 仍 open，已诊断为与本 PR 改动无关的临时 CI、安装或基础设施故障，且
正常 rerun 明确被权限拒绝。需要批准的工作流、保护规则阻断、确定性故障及结果未知
不适用。必须确认 head 是本任务可独占改写的分支，具有写权限，没有 WIP、重写禁令、
未知或他人的提交。优先处理已经需要的真实修复，能正常合并为一次推送时不额外重写。

全部条件满足后，Agent 才能在保留提交意图、代码树、父提交、作者及仓库 DCO 要求的
前提下 amend。这会改变提交 SHA。推送必须使用明确目标及
`--force-with-lease=refs/heads/<branch>:<先核验的远端SHA>`。远端出现插入提交即终止，
不能刷新 lease 后盲推。随后核对新 SHA 确实进入原 PR，以及 CI 是否真正启动；启动
不代表通过。

现有跟进 gate 在任何 amend 前占用**本机每个 PR 一次**的额度。观察状态旁的小型
`.ci-retry` 文件通过排他创建保证一次性，换 SHA、重启、重置观察状态或中途退出都
不返还，也不随 trace 清理。不得通过删文件、换状态目录或重置额度再次尝试。结果
未知时先核对远端，不能重推。该 PR 后续即使出现不同故障，也没有第二次仅为 CI
恢复重推的额度。

插件沙箱不直接运行 Git，也不能机械判定日志故障及分支归属。这些事实核验和 Git
操作仍由既有任务 Agent 工作流及任务授权承担；gate 确定性限制的是次数，不是这些
事实判断。不新增平台 scope、凭证、宿主 runtime 或服务端改动。开关不授权空提交、
裸 force、合并、auto-merge、队列操作、主干直推或改权限。
