# Test Environments：正式账号方案与交接

[English](test-environments-handoff.en.md)

2026-11-09 按接手者目标修订。PR #279 仍为 Draft，未安装、未发布，不能据此宣称真实账号已完成验收。

## 目标

保留 **启动 → 选账号 → 准备样本 → 执行验收 → 停止** 全流程。
账号使用应用原有的正式账号，同一身份可在不同电脑分别登录；不制造绑定单机的测试账号。
隔离档案只负责分开本机数据，并不限制账号在哪台电脑登录。

“记住登录”分两层：应用用既有凭证库保存其所有已登录账号的加密会话；插件记住公开
账号引用、本机档案及观察状态。停止/重启、目录元数据编辑和插件升级不登出、不清空这些档案。
新电脑正常登录一次后保留当地登录。过期、撤销、主动登出或删除应用数据仍需重新登录。
本方案不复制 token、Cookie、钥匙串、加密凭证文件，也不承诺无限期免登录。
账号发现限定于本插件启动并核实归属的目标应用，不扫描日常宿主或任意电脑的历史登录。

## 实现落点

| 模块 | 职责 |
| --- | --- |
| 插件 `node/core.cjs` | 项目/账号/方案/用例目录、启动计划、显式账号切换请求、工作流说明 |
| `node/account-catalog.cjs` | 自动合并应用保存的全部公开账号和本机档案历史，不持有凭证 |
| `node/session-monitor.cjs` | 观察实际身份、单次请求切换、缺少登录时等待、联网核验、记录状态 |
| `node/observation.cjs` | PID/进程身份/端口/主页面归属校验，固定应用操作、结果筛选与截图 |
| `node/cindy-launch.cjs` | 复用项目 restart 协调器，保留检查，只接管最终就绪等待 |
| `node/runner.cjs`、`terminal.py` | 本次进程监管、macOS 后台 PTY、等待与精确停止 |
| `manage.*`、`main.js`、`node/worker.cjs`、`node/cli.cjs` | 管理页、AI 工具和 CLI 共用同一实现 |

以上插件路径相对于 `test-environments/`。本轮没有修改客户端/服务端，没有新增第三方 OAuth scope。
新增 `select_account` 工具只作用于已核实的本插件运行；不是任意 IPC/JS 或宿主账号读取入口。
旧 `import_cindy` 改为从准确的活动实例同步公开引用，不再读取开发别名文件。

## 复用的现有客户端/服务端能力

检查了客户端本地源码，并读取 GitHub main 的 `authManager.ts`、preload、启动协调器、
`devStartupStatus.ts` 等关键文件；本地服务端检出较旧，因此另核对 GitHub main 的认证路由和托管回调。
源码存在不代表某版本客户端已发布或服务端生产已部署。

- 命名 `--isolated`、restart 协调器与 `.dev-instances` 实例登记。
- 应用已有账号列表、同步、切换、普通登录、认证刷新及数据库就绪接口。
- 既有 `--passive` 关闭定时任务/例程自动触发；不是关闭所有后台进程。
- 既有远程被控开关。验收方案默认关闭，并核对实际值。
- 服务端已有托管浏览器登录回调与客户端轮询；本轮不新增设备授权服务。

不再依赖旧交接的客户端 `dev-acceptance-profiles`、服务端 `feat/dev-device-authorization`
本地未提交 WIP，不要求接手者取得它们。不传旧验收参数，也不要求专用 acceptance 回执。
`loginSource` / `serveLogin` 旧配置仍可读取，但执行明确拒绝并提示改用各电脑正常登录。

## 当前工作流与边界

1. 保存项目和持久桌面档案，设置未占用的 debugPort。先不选账号也可启动并正常登录。
2. 插件观察该应用保存的全部账号，自动记住引用及档案；管理页可刷新、编辑展示名。
3. 选择已记录账号供下次启动使用，或对本次 job 发出显式切换请求。
4. 本机没有目标账号登录时保持等待，不从其他电脑/日常档案复制会话。
5. 应用启动 ready 不是登录成功。插件另行核对实际账号、联网认证及数据库。
6. ready 后通过实际应用工具准备命名样本，按已保存用例操作并记录证据，最后停止。
   方案返回完整 workflow；样本与用例不会因保存、启动或登录而自动变成通过。
7. 切换遇到断连/超时等不确定结果时，先观察实际状态，不自动重复切换。

`mode:legacy` 保留原启动和登录路径，不做账号监管。iOS/Android 的构建/Metro 和 Baguette
交接保留，不能把桌面账号能力宣称为移动端已验收。通用 argv 适配器保留各项目自有
prepare/verify 命令，不转换不同应用认证格式。

## 证据和待办

版本 1.0.5 的新代码有目录持久化、应用接口投影、A→B→A 状态机、双电脑独立登录模型、
切换不确定不重试、锁冲突、删除后不复活，以及真实子进程/PTY/归属检查回归。
协议集成用本机 HTTP/WebSocket 模拟应用，经过真实 runner、lsof 和 CDP 传输；
不使用真实账号或真实凭证。这不等于真实 Cindy 账号的集成验收。

旧版 1.0.4 + 缺失客户端 WIP 的实测只保留为历史背景，不能证明本轮新适配器正常。
当前仍需：

1. 在真实 Cindy 开发版验证正常登录、自动记住所有账号、停止/重启后复用及 A→B→A。
2. 在第二台电脑独立登录同一个正式账号，核对身份、样本归属及原电脑登录保留。
3. 验证授权过期/撤销、登录等待、账号切换时数据库与后台开关，以及普通启动回归。
4. 补管理页/AI 工具/CLI 的真实宿主集成；核对实际客户端版本和渠道。
5. 若需人在另一台设备完成首次授权，再评估最小登录链接交接接口并实测现有托管回调。
   来源档案直接授予空档案身份是另一项未实现能力，不是本轮依赖。
6. iOS/Android、Windows、Linux、Filo 等分别补适配与实测；Windows 账号监管目前明确不可用。

测试通过后仍保持 Draft，直到上述与交付范围相关的真实集成缺口得到补齐。
运行私有账号、日志、截图和数据档案不上传本 PR。

## 续跑

在仓库外指定独立 `TEST_ENVIRONMENTS_HOME`，使用
`node test-environments/node/cli.cjs <method> --stdin`；先 catalog/plan，再按授权 start。
目标开发应用不需要安装本插件，不启用未完成版本到日常宿主。

```sh
node --test .tests/plugin-contract.test.mjs .tests/localization.test.mjs .tests/provisioning.test.mjs .tests/publish-workflows.test.mjs .tests/test-environments.test.mjs
```
