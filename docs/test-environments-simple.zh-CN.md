# 1.2.1：选项目，然后启动

[English](test-environments-simple.md)

首页只保留本机/SSH、项目和启动。运行后只有一个状态面板，按实际状态提供登录提示、
已配置的准备/验收脚本、截图/结果和停止操作；不再摆五步卡片和项目创建表单。

## 怎么用

1. 点“选择项目…”，在 **Cindy 原生目录窗口**中选择源码文件夹。
2. 点“启动测试”。首次在目标应用正常登录，之后复用同一测试档案。
3. 运行中按提示准备样本、检查用例，截图在停止前取，最后点停止。

选择和取消本身不启动应用。重复选择同一个真实目录会复用原项目和档案，保留账号选择，
不要求另填名称、路径、标识、隔离名或创建方案。非默认项目参数、历史和技术详情仍在高级管理。
远程流程继续先预览精确 PR 版本，再明确启动；截图和正式账号边界不变。

## 复用了什么

- 使用已公开的 `cindy.pick({mode:'directory'})`，由 Cindy 负责原生窗口、亲选授权、取消、
  限速、忙碌与目录台账；插件不复制宿主选择器，不扫描宿主项目数据库。
- 所选绝对路径只从主机交给插件 main → Node 服务，页面收到项目/配置引用，不回传原始选择结果。
- Node 原子复用/创建测试引用和默认配置；不创建、重命名或删除 Cindy 全局项目。
- 新增 `pick:true` 声明仅用于亲选目录；已有 node 本机文件权限不扩大，未申请 workspace 或后台 Agent 能力。
- 目录选择只由用户点击发起。取消不保存、不启动、不重弹；不支持时明确提示使用执行电脑/高级管理。
  窗口打开期间同一请求保持去重，收到主机确认后停止重发；新选择最长等待 30 分钟。

Cindy 的 `useProjectPickerOptions`/`FolderPickerPopover` 使用最近目录和别名，但它们是客户端内部组件，
当前插件 API 不提供那份“最近项目”选择器。本次复用的是已有原生目录接口，不能声称已共享最近项目列表。
未复制私有组件、未偷读宿主数据库，也没有为此新增主程序代码。

核对源码：Cindy `70eb974da4d3792cc5feabc8bdc9ee1e1f06233d` 的
`apps/desktop/src/main/cindy-brain/pickSlot.ts` 与 `apps/desktop/src/renderer/hooks/useProjectPickerOptions.ts`；
SDK 依据当前宿主 Forge 的 §4.14。原生选择接口需宿主支持，缺失时保留其他功能并明确报错。

## 证据边界

测试覆盖原生 SDK 请求的桥接、取消、长等待去重、不可用/忙碌、项目复用与不自动启动，
以及真实浏览器点击、解包、实际 Git/OpenSSH 回环。浏览器中的原生选择返回值是明确的测试适配，
不能冒充已经在实际 Cindy 系统窗口亲选成功；正式账号、真实双机与硬件仍需相应实机证据。
