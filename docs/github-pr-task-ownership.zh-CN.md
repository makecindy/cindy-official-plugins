# 同一 PR 只开一份跟进，任务由用户选择

同一个 PR 可以在多个任务里有卡片。没有任务跟进时，每张卡片都提供「自动跟进到合并」，不永久归属第一个展示它的任务。单纯展示已有 PR 不触发自动改名或自动跟进；从待发布卡片创建 PR 时，仍按用户设置执行一次发布后的操作。

插件以宿主注入的 session_id、仓库和 PR 编号识别跟进关系。已开启、正在开启、正在停止都占用跟进位置；空闲卡片不占用。按钮先保存占用再交给 Agent；Agent 开始前用 claim_follow=true 申请，仅成功且 follow_claimed=true 才能创建定时任务。明确拒绝交接时释放；结果未知时保留，先核对。占用记录跨插件重启保留，不被普通历史清理删除。

其他任务跟进期间，本任务的卡片保留 PR 状态，写明「其他任务正在跟进／开启跟进／停止跟进」，只有卡内「打开跟进任务」入口，没有操作、设置或归档按钮。工具返回 existing_task、空 todo 和 follow_claimed=false。不要在卡片外重复链接。每个任务保留自己的卡片记录；刷新复用同一张卡片，不改写其他任务的记录。旧卡片的按钮执行前也会检查，防止同时开两份。

停止必须先删除定时任务并核实，再回报 following=false；然后用户可以换任务开启。暂停中的定时任务也要先处理，不能直接另开。技能创建前查询已有定时任务，包括暂停项；没有卡片元数据的旧跟进在原跟进任务中核对。通用调度器没有 PR 唯一约束，不同电脑的独立插件安装也不共享这份本地记录。

PR 状态沿用宿主实时状态槽。跟进关系在刷新卡片或点击时重算，不会主动改写其他任务里已经结束的卡片调用。宿主的跨任务更新限制保持不变，所以旧卡片可能暂时仍显示旧按钮或旧跳转入口，刷新后才切换；旧按钮不能通过本插件启动重复跟进。发布验收应明确这个限制，不应宣称跨任务瞬时同步。

缺少任务标识的旧卡片：仍在跟进的要在原任务显式刷新后认领；空闲的不会阻止其他任务开启。已有重复定时任务不批量删除。记录无法读取时停止申请；归档或删除任务不会自动释放仍在跟进的记录。

卡内导航需要宿主配套支持严格的 cindy://session/<id>，不允许任意应用命令。宿主先发布，再锁定真实兼容版本发布插件。没有新增 GitHub/OAuth 权限。
