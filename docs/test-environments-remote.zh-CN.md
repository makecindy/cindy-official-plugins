# 第二阶段：通用 SSH 验收与首次授权

[English](test-environments-remote.md)

## 两项独立能力

1. **SSH 远程编排**：A 的 AI 通过 SSH 指挥已登录的 B。按精确 commit 检出指定 PR，
   在独立工作树构建/启动，复用 B 档案，准备样本、执行验收、停止本次实例，再取回证据。
2. **跨设备首次授权**：B 未登录时研究 A 确认后给 B 签发自己的设备会话。
   先核实当前客户端/服务端能力；不假定托管浏览器回调等于已有设备授权。
   该项不阻塞第一项，也不阻塞第一阶段交付。

SSH 只承载命令和证据。禁止复制认证文件、Cookie、钥匙串或 A 的设备会话代替授权。

## 通用模板，而非固定电脑脚本

每次选择 SSH Host（别名/主机名）、远端 Node 路径、PR 所属仓库和精确 SHA、B 的源码仓库路径、
B 的已保存档案及验收项目。常用电脑可以复用已有 SSH 配置与 B 本机档案。
硬件型号来自 B 的实际探测，不能把“SSH 连通”当作设备或手感已经验收。

不保存 SSH 密码/私钥，不自动接受新主机密钥，不转发 A 的 agent。
依赖选定电脑已安装 SSH、Node、Git、项目构建工具链及必要图形会话。
每台电脑只需事先准备这些基础条件和自己的登录；业务模板不按电脑写死。

## 接口设计（第一阶段仅预留，第二阶段实现）

- `remote_catalog(target)`：探测目标平台/型号并读取 B 的公开项目、档案、账号引用。
- `remote_plan(target, profile, pr)`：读取 B 档案，预览固定版本的检出/启动和人工/设备步骤。
- `remote_start(planId)`：按已预览的电脑、仓库、PR/SHA 和档案启动，返回持久运行 ID。
- `remote_status(runId)` / `remote_stop(runId)`：断线后查同一次运行，停止只作用于本次任务。
- `remote_collect(runId)`：仅取本次运行的日志、私有截图和结构化结果，校验大小与摘要。
- 样本/用例执行通过项目已声明的命令及实际应用/设备工具，结果带执行来源，不把状态查询当作验收。

运行记录需包含目标、PR/SHA、实际 checkout、实际平台/型号、档案引用、阶段、远端 jobId、
证据清单及每项验收的来源。开始成功回执不等于登录、构建或验收成功。
断连/超时保留执行未知状态，必须先查询原运行，不生成新 ID 盲目重试。
只在新工作树检出，不覆盖 B 的工作区，不广泛杀进程，也不默认删除保留的日志/工作树。

## 真机和人工步骤

- 实体手机必须交接给该目标上可用的设备工具，核对设备 ID 和安装版本。
- 触控板手感、连续反向等需要真实输入的项目明确标为人工待验。
- 合成事件、独立窗口和模拟器证据不能冒充真实侧栏、实体机或人工操作。
- 收集到的材料先留在当前任务私有目录，经检查脱敏后再由用户/AI 按授权整理到 PR，不能自动外发。

## 已知能力与证据缺口

当前源码已有 SSH 管理基础、隔离启动、账号切换、托管浏览器回调。插件不导入客户端私有模块，
也不复用其中复制其他 Agent 授权文件的辅助路径。优先调用系统 OpenSSH 和第一阶段共享 CLI。
跨设备首次授权的授权方身份、目标设备绑定、时效、拒绝/撤销和独立会话签发仍需协议评估。

第一阶段证据只覆盖其当前实现。第二阶段应新增命令注入、错误主机/仓库/SHA、断线未知、
独立工作树、证据越界/大小校验及实际 SSH/硬件验证。没有选定的真实 B 时，可以验证模拟传输和
本机 Git/进程链路，但必须标为模拟，不能宣称跨电脑真机验收已完成。
