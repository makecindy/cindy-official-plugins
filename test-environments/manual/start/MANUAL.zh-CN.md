# 测试环境

## 用户页面

页面只管添加和选择真实账号，并显示登录档案所在位置。首次没有可用客户端时，引导用户在右侧对话请求启动客户端，然后点“添加账号”。登录始终在客户端自己的页面完成。账号出现后点“使用这个账号”，插件记住下次测试的选择，不立即切换当前应用。页面没有项目、PR、目录、测试包、API 或样本配置。

## 对话如何使用

1. 从当前任务确定要运行的客户端源码和版本，复用当前任务上下文；不要让用户在插件页面重新填目录、名称或配置表。通过 `catalog` 查看已有配置，缺少时由对话用 `save_project` / `save_profile` 准备。保留稳定隔离名称和可用 debugPort；不修改日常 Cindy 档案。
2. `login_accounts` 返回应用实际记录的账号、档案位置和 `selectedAccount`。可传 `account` 记住用户选择。列表的 available 只表示曾观察到档案，不证明授权有效。
3. 添加账号调用 `add_account({project,region})`，打开兼容客户端已有的登录页面。省略参数时必须有唯一明确的客户端环境；歧义返回 ACCOUNT_CONTEXT_REQUIRED，先在当前对话解决。此操作可能启动实例；保留返回的 jobId，不能因等待登录而重复启动。返回 requested 仅表示已登记请求，需查 status 和实际客户端。用户输入密码/验证码/SSO 确认，插件不接触这些内容。
4. `bind_login_account({project})` 默认使用页面选中的账号；明确另选时传 `account`。复用应用保管的持久档案，旧客户端未报告区域时沿用观察到的档案版本，不凭邮箱推断区域。相同档案不能并发启动。先 `plan` 再 `start`，查询 `status` 核对真实账号。
5. `ready / application-account-online` 表示当前账号、在线授权和数据库可用，不代表测试通过。使用账号已有数据，按当前任务确有必要时才准备样本和操作；无需配置业务 API、制造测试身份或注入假数据。
6. 通过现有应用/设备工具执行验收，保留实际证据；`inspect` 可保存私有截图。`stop` 后继续查到 stopped，保留应用档案供下次复用。

## 保留与失效

凭证由目标应用加密保存，插件只记录公开账号引用和档案位置。停止、重启、插件升级不删除档案。默认约30天滑动续期以服务端配置为准；插件不为闲置账号后台续期。退出、过期、撤销或删除应用数据后需正常重新登录，不承诺永久免登录。每台电脑分别授权，不复制另一台机器的凭证。页面选中账号不会自动替换正在运行的账号；当前实例切换需通过 `select_account` 明确请求并核实结果。

## SSH 与限制

对话使用 `remote` 的 catalog / plan / start / status / select_account / action / stop / collect。每次提供目标电脑，不写死个人机器。先查目标档案与工具链，再预览实际 PR SHA，按返回 runId 启动、查询和取回本次证据。断线后查同一运行，不能盲目重启。SSH 是控制与传输通道；B 使用 B 自己的登录态，跨设备首次授权未实现。日志分享前脱敏，不自动上传 PR。

当前固定桌面适配器只访问核实 PID、进程身份、端口和主页面的自有源码启动实例，调用现有应用能力，不接受任意 JS 或调试 URL。任意安装包隔离启动、日常宿主直接授予测试档案身份未实现。Windows 账号监管不可用，Linux 待实机验证。移动设备交给 Baguette，真实触控板手感等保留人工步骤。真实账号与第二台电脑的集成证据仍需补齐，测试替身不能标为实际登录验收通过。

命令适配器及 prepare/verify 脚本退出码只能证明对应命令结果，不能证明账号、业务操作或硬件验收通过。不传缺失 WIP 的 --account/--fixture/--login-source 等参数。不在工具、日志、配置或证据中存密码、令牌、Cookie。
