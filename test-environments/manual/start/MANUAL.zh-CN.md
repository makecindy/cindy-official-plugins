# 测试环境

## 1.3.0：多账号复用，仅插件

首次选择项目和版本，在测试应用原有入口登录。之后调用 `login_accounts` 列出本机已发现账号，
用 `bind_login_account({account,project})` 为另一个源码项目复用原档案；返回的 profile 可直接预览、启动。
界面从“已保存的测试账号”选择，展开“应用保管登录态的位置”查看路径。旧版公开目录会自动接入。
客户端没有账号区域字段时，按已观察到的档案版本启动，不猜账号区域，不需要新增客户端或服务端接口。
停止保留应用数据；默认约30天滑动续期以服务端为准，列表中的闲置账号不会由插件后台续期。
不得宣称永久登录、日常宿主直接授权或任意桌面包隔离启动已实现；不读取/复制凭证。


## 最简单的用法（1.2.1）

点“选择项目…”使用 **Cindy 现有的原生目录选择窗口**，选中源码项目后直接点“启动测试”。
不再填写路径、项目名称或创建方案；默认配置自动保存，重复选择同一真实目录会复用原项目和档案。
选择或取消本身不会启动。运行后只有一个状态面板，显示登录提示及已配置的样本/验收、截图和停止操作。
原来的完整配置、技术详情和历史仍在“高级管理”；SSH 仍先预览精确版本再启动。

插件使用已公开的 cindy.pick，并未复制 Cindy 内部的项目下拉组件或扫描宿主项目数据库。
这次复用的是原生目录选择，不宣称已接入宿主“最近项目”列表；Cindy 目前未向插件开放那个组件。
新增 pick 声明只用于用户亲自选目录，现有 node 的本机权限不变；取消、忙碌或不可用时不自动重弹。
作者显示字段仍省略，不改写历史提交与贡献者。

## 正式账号与登录保留

使用应用原有的真实正式账号，不制造只能在一台电脑使用的测试身份。
每台电脑需正常登录一次；之后可在该电脑应用档案中复用，遵循应用原有会话策略。
这不等于同步凭证或迁移整份本地数据。

保持相同的持久隔离名称即可复用该档案自己的登录和数据。可在一个档案中通过应用的
“添加账号”保存多个正式账号，也可分别使用不同档案。验收运行受监管期间，插件自动
观察应用保存的全部账号，记录不透明 accountKey 和本机档案引用。若刚登录就停止，
应用已提交的登录仍保留在凭证库，下次运行再发现。应用本身没有保存或已登出的账号
不能靠插件恢复登录。

`catalog.accounts[].sessions` 记录本机档案位置、最近是否在账号列表及历史登录观察，
不是令牌库，也不能证明授权仍有效。凭证始终由应用加密保存。
不要在插件字段、命令、工具参数、日志或导出中放密码、令牌、Cookie 或复制的凭证文件。
停止、移除目录记录不登出或删除应用档案，插件升级也不替换它。
过期、撤销、应用登出或应用数据被删除后，需要正常重新登录。

`import_cindy({project,jobId})` 可手动从准确的本插件实例刷新公开账号引用。
只有一个匹配的活动实例时可省略 jobId。不再读取未交接的开发别名文件，也不扫描日常宿主。
账号展示名称可编辑，selector 不可改绑身份。旧昵称 selector 需换为新发现的正式账号引用，
再在启动方案中选用。

## 完整验收流程

1. 保存 Cindy 源码项目和桌面方案，使用 `mode:acceptance`、稳定 `isolated` 名称及
   未占用的 `debugPort`。默认关闭远程被控和后台自动触发。
   `background:off` 复用 `--passive` 关闭定时任务/例程自动触发，不关闭认证刷新或所有后台进程。
2. 先 `plan`，再只调用一次 `start`。保存 jobId 并查询 `status`，等待时不重复启动。
3. 在本机目标应用的正常界面登录并添加其他正式账号，插件自动记录。
   在方案中选账号供下次启动使用；或调用 `select_account({jobId,account})` 请求本次切换。
   `account` 是目录 ID，不是展示名或令牌。
4. 等待 `ready / application-account-online`：当前账号需已登录、符合选择、通过应用的
   联网刷新且数据库可用。等待登录不计入启动超时；本机缺少登录时等待用户正常登录。
   应用启动回执或账号出现在列表中，都不能证明已认证。
5. 读取 `plan.workflow`，通过实际应用工具准备命名样本并执行已保存用例的操作。
   `fixture` 是样本说明名称，不是注入客户端的参数。样本使用易识别名称并按账号区分。
   记录实际结果和证据；ready 不等于验收通过，样本/用例状态在 AI 实际验证前仍为
   `not-verified / not-executed`。
6. `stop` 后继续查询直至 stopped。只停止本次进程组及已核实实例，保留所有账号和本机数据。

切换结果不确定时不自动重试。先核对实际账号/登录状态，再明确请求切换。
监管进程异常退出返回 unknown，不按宽泛进程名杀进程。
同一项目根目录仅允许一个活动启动；刚停止时附属进程可能尚在退出，需保留归属检查。

## 复用现有项目能力

Cindy 复用导出的 restart 协调器，保留隔离、迁移、依赖、资源与进程冲突检查。
只在最终启动阶段把 `--wait-ready` 等待交给插件。
不依赖 `dev-acceptance.mjs`、专用 acceptance 回执或旧
`--preset/--account/--fixture/--login-source/--serve-login` WIP 参数。
`loginSource` / `serveLogin` 作为旧字段保留读取，执行时明确报未实现。
新电脑通过正常流程登录，不搬其他档案的凭证。
`mode:legacy` 保留原始启动/登录语义，不进行账号监管。

固定 CDP 适配器连接前核对 PID、进程启动身份和端口归属，并且只连接唯一主页面。
仅调用已有应用 API，返回筛选后的非秘密结果，不接受任意 JS 或调试 URL。
`inspect` 可在桌面锁屏时保存私有截图；这不代表已完成登录或批准系统凭证弹窗。
新实现尚未完成真实 Cindy 账号集成验收。Windows 的账号监管明确不可用；Linux 仍待实机验证。

服务端已有托管浏览器登录回调，但把登录链接交给另一台设备的入口本轮未实现。
已登录来源档案给空目标档案授予身份也未实现。
复用目标应用在本机已有的有效登录不依赖这两项功能。

其他项目使用 `command` 适配器和其文档支持的 argv 数组，例如
`{"start":["node","scripts/dev.mjs","--data-dir","{dataDir}"]}`。
可替换 profile、account、isolated、fixture、remoteControl、background、platform、dataDir。
可选 prepare/verify 命令属于项目自身；不隐式使用 shell，也不转换不同应用的认证格式。

iOS/Android 准备构建或 Metro 后，按 `plan.handoff` 交给已安装 Baguette：选择准确设备、
安装并确认 matchesLocal、启动、登录并检查样本/用例。
桌面账号监管不代表移动端登录已实现；不恢复被取消设备，不虚构应用参数。

## 独立开发

使用 `node <插件源码>/node/cli.cjs catalog`；参数通过 `--stdin` JSON 输入，
例如 `plan` 输入 `{"profile":"daily"}`。
`TEST_ENVIRONMENTS_HOME` 放在仓库和插件安装目录之外。执行电脑需已有 Node、项目工具链、
macOS PTY 所需 Python 3，以及核对端口归属的 lsof。

目录、日志和截图留在本机用户数据。分享日志前检查脱敏。
不要把未完成版本启用到日常宿主，也不在目标 dev 中安装本插件以启动下一层。
打包不等于安装。

本机验收与通用 SSH 编排统一在 PR #309 和同一个测试包交付、分别记录证据。#308 已被替代，#279 保留交接来源，不再要求前置 PR 先合入。跨设备首次授权仍是后续独立研究，未实现或部署。

## 通用 SSH 模板（统一测试包）

统一测试包 1.2.1 同时包含本机验收与通用 SSH 编排，电脑是参数，不是固定目标。
通过 AI/CLI 先 remote_catalog(target) 读目标电脑的档案和实际型号，再 remote_plan(target,profile,pr,requirements)，
检查计划后用返回的 runId 调 remote_start；后续 remote_status、remote_select_account、remote_action、
remote_stop、remote_collect 始终引用同一运行。target.host 是已配置的 SSH 别名/主机名，target.node
可选为 B 的 Node 绝对路径；pr 提供 GitHub owner/repo、number；可选 commit，不填时从目标 Git 读取并预览精确版本。
B 需已有本机验收档案、源码仓库、SSH 主机信任和项目工具链，账户及其加密登录态留在 B。
prepare/verify 只执行项目保存的参数数组；不接受临时任意远端命令。没有项目命令或设备工具时明确交接待办。
requirements 中 human/device-tool 项目保持 pending，不能用合成事件或命令退出码当作真机/人工通过。
证据仅包含本次结果、可选限量日志和私有截图，校验摘要，绝不复制登录文件或自动发往 PR。
日志可能有项目输出，分享前检查脱敏。SSH 断线后查同一 runId，不能盲目重新开始。
跨设备首次授权另行研究，B 未登录时正常等待授权，不阻塞已登录 B 的编排。
当前只有模拟 SSH + 本机真实 Git/进程测试，没有跨电脑、真实账号、实体手机或人工手感验收。

AI 实际调用统一 `remote` 工具，以 operation 选择 catalog/plan/start/status/stop/select_account/action/collect。文中的 remote_catalog 等名称也保留为 CLI/内部流程入口；不是八个独立宿主工具。

停止请求后拒绝新动作和账号切换；启动中的动作会补收停止请求。同一 runId 的本机请求串行处理，
忙碌时等待回执；进程退出留下的锁按进程启动身份核对后恢复，不信任复用的 PID。
remote_status.accounts 返回本次运行发现的账号目录 ID，供 remote_select_account 使用；不包含登录凭证。
每次 collect 先验证完整清单，再生成独立证据子目录；旧截图不会混入新结果，失败不交付半套文件。

项目配置 prepare 命令后，桌面方案卡片也显示“准备样本”，可从界面完成启动、准备、验证和停止。
已经联网核验过的本机登录态失效后持续提示重新授权，不自动重试账号切换。
