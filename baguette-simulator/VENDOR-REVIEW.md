Existing Baguette/runtime versions, network destinations, permissions and Xcode preferences are unchanged. `vendor-web.patch` is the complete diff, with context, against the v0.2.10 release archive's `Web/` (byte-identical to `Sources/Baguette/Resources/Web` at the tag), regenerated with no offsets after the rotation change below (v0.2.8 added the `sim-notify.js` card, shipped unmodified; v0.2.10 gives the 3D stage its own `Baguette._Keyboard`, which therefore also uses the patched `/clipboard` path). These ten Web files differ (nine carried-forward patches, the reviewed Duo edge-drag fix, and the 0.2.7 Defaults toggle removal):

- `stream-session.js`: bounded reconnect after unexpected socket close; cancel scheduled reconnect on deliberate stop.
- `baguette/parts/keyboard.js`: delegate key/text/clipboard actions to the same-origin /clipboard private-device bridge (fragment port never selects a destination), suppress OS repeats and duplicate in-flight paste, serialize keys/paste/copy, report queue overflow with English fallback for added input errors, drop unsent keys on blur/hide/detach/release.
- `baguette/parts/bezel.js`, `baguette/carplay/carplay-frame.js`, `sim-native.html`: standard arrow cursor instead of crosshair.

- `farm/farm.html`: remove remote font/preconnect links; keep the existing system-font fallback and all Device Farm controls.
- `sim-location.js`: map tiles/search use same-origin `/map/` routes; the Node worker validates coordinates/query length and sends HTTPS only to fixed OSM hosts, with no redirects or forwarded credentials.
- `sim-native.js`: toolbar labels use textContent, preserving literal text instead of interpreting DOM-sourced titles as HTML.
- `sim-3d.js`: fallback selector escaping uses CSS hexadecimal escapes for every code point, including backslashes and quotes.

The first-party `native/keyboard.m` adapts Baguette’s SimulatorKit ABI and device resolution (Apache-2.0); its source and `native/build.sh` accompany the ad-hoc signed Apple Silicon binary. It waits for every delivery completion, releases keys on partial failure, refuses a foreign/default device set and serializes helper access using a per-device lock. It does not restart SpringBoard or extract clipboard/account contents.

- `sim-native.js` (rotation): upstream rotates the bezel with a CSS transform inside the portrait-sized layout box, so a landscape device is clipped; the patch swaps the frame's width/height while landscape and re-centres it (`fitRotatedFrame`, rerun on resize), adds `__nativeRotateBy(step)` for left/right rotation and `__nativeOrientation`. Loading/boot completion no longer writes portrait or a remembered browser value to the guest. Flat views restore a per-device localStorage viewer pose before their first paint, without animation. A known pose survives reconnects: an app/AX orientation (for example portrait-only Home on a sideways phone) must not override the bezel. Only views without a known pose seed it through the existing `describe_ui` WebSocket message (one-point hit test). Unavailable storage still preserves the pose in page memory; invalid storage is treated as unknown. Retired-stream responses and responses overtaken by manual rotation, including a complete turn back to the starting pose, are ignored. Flat viewer screenshot exports capture one native framebuffer and rotate it to the displayed pose; dimensions come from the captured PNG, with no AX/input geometry probes or lower-resolution video-frame copy. Agent captures and viewer exports without an explicit flat pose retain live geometry/panel checks. Foldable panels retain the existing live hinge/lit-panel path. Template, device metadata and hinge reads run concurrently to shorten page reconstruction. Only explicit rotation uses the existing `/orientation` route; no new endpoint, network destination, download, execution or credential handling is introduced.
- `sim-native.html`, `sim-native.js` (0.2.7): remove the Defaults card toolbar button and its overflow-menu row. The card scripts stay unchanged but cannot be opened; `node/viewer-proxy.cjs` returns 404 for its routes (see the 0.2.7 review).

## Outbound-domain and execution scan

Source URL scan of all vendor JS/HTML/CSS/JSON identified:

- `nominatim.openstreetmap.org`, `tile.openstreetmap.org`: pre-existing optional location search and map tiles (`sim-location.js`). User-triggered functionality now routed through the autonomous Node worker fixed endpoints; browser requests stay same-origin.
- `fonts.googleapis.com`, `fonts.gstatic.com`: removed from `farm/farm.html`; existing CSS system-font fallbacks are used without font downloads.
- `leafletjs.com`: library attribution; `bugs.chromium.org`, `bugzilla.mozilla.org`: CSS comment references; `www.w3.org`: SVG namespace constant. These are not added runtime API clients.
- `127.0.0.1`: the added clipboard bridge; exact Origin and random capability required (persisted with the port in a 0600 file under the BaguetteCindy data directory so open tabs reconnect after a Worker restart; retired when simulators are turned off), request body capped at 40 KB, no clipboard content logging.

No eval/new Function calls or added executable base64 blobs were found in the ten modified upstream files or first-party Node/native code. Leaflet contains its upstream embedded transparent GIF and CSS assets; no executable payload was added. The full Baguette binary includes more upstream capabilities than the 16 exposed Agent tools: this PR does not claim to audit every native feature by reading JavaScript. Native binary and new plugin admission require maintainer review; the runtime’s own private-framework ABI is not a stable Apple API.

The plugin declares Node and loopback preview, uses fixed executable paths and argument arrays (never shell interpolation), no managed credentials, and launches Baguette with `--no-plugins`. Simulator apps retain their own network/auth state; App input may still trigger external actions. No command download occurs at runtime. Dependency licenses from the upstream tag’s Package.resolved (including build/test-only packages) and Leaflet 1.9.4 are reproduced in THIRD-PARTY-LICENSES.txt.

## Known limits and verification boundary

Native WebSocket disconnect SIGABRT was observed with 0.1.98. On 0.2.7 with Xcode 27.1 / iOS 27.1 it did not reproduce: about 25 minutes of three concurrent loops opening and dropping flat and 3D streams (clean close and TCP reset, 0–800 ms holds) left the same server process running (2026-10-21). Bounded recovery is preserved. Worker shutdown also stops the controller. Browser session ownership is separate from persistent simulator data. Historical tests cover the bridge and real iOS 27 native input. The installed 0.2.0 candidate checks and the 0.2.7 local smoke are recorded below and in VERIFICATION.json.

The proxy bootstraps an HttpOnly SameSite=Strict capability cookie only from a token-authenticated control request. All proxied viewer HTTP, map and WebSocket routes require it; credentials are stripped before HTTP forwarding. The empty controller shell is public so its fragment can authenticate. This protects the proxy, not against same-user processes that can access CoreSimulator or the upstream Baguette loopback listener directly. Manual restart excludes only the retired child from crash accounting.

Minimum OS evidence: `xcrun vtool -show-build` reports `LC_BUILD_VERSION minos 15.0` for both bundled Baguette and native/keyboard. The worker checks `/usr/bin/sw_vers -productVersion` before launching either binary and rejects older or unrecognized versions with UNSUPPORTED_OS.

Viewer transport boundary: these scripts run in the external page opened by `cindy.preview`, not the plugin sandbox/Panel. Keyboard requests use relative `/clipboard` on that already-open preview origin; no hostname or port is chosen from input. `main.js` uses `cindy.node.request` to start the declared Node runtime and `cindy.preview` to open its declared preview host. The page has no `cindy.fetch` API. External OSM requests remain in fixed-endpoint Node code.

Native helper update: releaseKeys submits HID usages 4–231 before waiting once on a dispatch group, with a shared one-second acknowledgment deadline. Missing callbacks no longer prevent subsequent key-up submission. A serial callback queue aggregates delivery failures; timeout returns failure without reading mutable callback state, and late callbacks retain their resources. Rebuilt with `sh native/build.sh` and verified ad-hoc signature. Updated native/keyboard SHA-256: `96a8eeb56f41ab6bab253e96a2e85398f9d7009f8a50cf250dbfc48dc4c623fd`. The macOS Objective-C regression compiles the production functions and uses actual dispatch queues, covering first/middle/last/all errors, no callbacks and delayed callbacks; it confirms all 228 submissions and a timeout under three seconds. This native regression is explicitly skipped on non-macOS runners. The keyboard helper binary is unchanged by the 0.2.0 upgrade; its Duo Unicode input was verified in the installed Cindy Beta package.

## Task page and management view (2026-10-21)

- `task.html` / `task.js` / `task.css` (manifest `taskView`) are the per-task simulator: a page in each task's right sidebar that embeds this plugin's own loopback controller in an `<iframe>`, so the live screen shows without browser chrome. The page reads its task from the `session` query parameter; each task is bound to one device (worker `task-bindings.json`). With no device bound it lists devices (use one, or create a new one); a bound device that is off shows a start card.
- `manage.html` / `manage.js` / `manage.css` (manifest `mainView`) are the cross-task management view: every private device with its state and the number of tasks using it, plus start, shut down, rename, create, and open-in-current-task.
- `main.js` binds the calling task to the device on `boot` / `open_viewer` / `launch_app`, opens the task page with `cindy.taskView({sessionId})`, and pushes the controller URL over `BroadcastChannel('baguette-pages')`. Hosts without `cindy.taskView` fall back to the sidebar browser (`cindy.preview`) unchanged.
- Host side (makecindy/cindy, `ghostPanelLoopbackEmbedAllowed`): a plugin that declares a page (`panel`, `mainView` or `taskView`), `node` and a loopback `preview.hosts` entry gets `frame-src 'self' http://127.0.0.1:* http://localhost:*`; the partition gate admits the page's loopback sub-frame, a nested sub-frame on the same host:port, and that frame's same host:port requests (scripts, XHR, WebSocket). The plugin pages themselves still cannot reach the network. The controller and the proxied device page answer `frame-ancestors 'self' cindy-ghost://baguette-simulator`, so only this plugin's own pages can frame them.

## Agent tool set rework (0.1.25, 2026-10-22)

No vendored file changes; first-party Node only. Driven by a review of past Cindy tasks (models injected events into game processes, downloaded AXe/idb, drove Device Hub windows with computer-use, slept and re-screenshotted, and tested stale builds).

- Tools are regrouped by intent within the host's 16-tool limit: `device` and `app` and `viewer` take an `action`; `runtime.cjs` routes each to the existing worker operations (`boot`, `open_viewer`, `launch_app` still bind the task). Host execution uses fixed command arrays, and remote shell arguments are individually quoted.

These are reviewed runtime behavior, not arbitrary downloaded code evaluation. The image supplied to OCR cannot choose a script, worker path, language download URL or executable. ## Streaming performance 0.2.23 (2026-10-24)

Measured before and after on the same Mac (M5 Ultra, Xcode 27.1, iOS/tvOS/visionOS 27.0, Emulator 37.1.11, API 36 arm64); the full table and method are in the PR.

`vendor-native.patch` adds three source changes and their tests on top of the version stamp and the 3D background fix. The full upstream suite passes (2555 tests in 306 suites).

- `StreamFrameSchedule`: emissions keep an ideal cadence (previous slot + 1/fps) instead of restarting from each late timer fire; a stream more than one interval behind restarts its cadence rather than bursting. iPhone H.264 at a requested 60 fps went from about 45 to 58 fps.
- `StreamFrameSchedule` / `StreamFramePump`: optional bounded repeats (`settleRepeats`) with a `settle` delivery for the final repeat and `revive()` to re-send the latest frame once.
- `AVCCStream`: drops unchanged SimulatorKit surfaces before pacing with the existing `SeedFilter` (rendered 3D screens are not filtered: GPU writes may reuse a surface without a new seed); repeats only six times after a change, the last as a forced keyframe, then sends nothing; a keyframe/snapshot request or a scale change re-sends the latest frame once. An idle iPhone stream went from about 45 fps and 10% CPU to no frames and under 1%. Each WebSocket session still owns its stream, so a new viewer gets an immediate keyframe on a still screen.

Rebuilt with `native/build-baguette.sh` from the same verified v0.2.10 source archive. `vendor/baguette/Baguette` SHA-256 `09550039ec4e03d300502d705698e0958ed637b605a7423fd8b4f46b8e54ca59`, 8,005,840 bytes; HingeControl rebuilt byte-identical. No route, host, download, injected code or `simctl` call changed; Web files are unchanged.

First-party changes:

- `native/android-encoder.m` (new helper, built by `native/build.sh`, ad-hoc signed, arm64): maps one viewer-owned frame file read-only, converts RGB888 to BGRA with Accelerate and encodes H.264 with VideoToolbox (hardware, low-latency rate control, no reordering). Reads commands on stdin, writes length-prefixed frames on stdout. No network, no other file access, never writes the shared file; exits on end of input.
- `node/android/stream.cjs`: the viewer creates an owner-only temporary directory, sizes the frame file to the longer edge squared ×4 bytes, and asks the emulator to stream RGB888 there (`ImageTransport` MMAP, `file://` URL, explicit size). Emulator 37.1.11 writes pixels only for an explicit size, and a bare path crashed one test emulator with heap corruption, so both are fixed in code. The file is deleted when the stream ends. At most one frame is in flight; a quiet screen ends on a keyframe. Display rotation is polled once a second instead of two adb commands per frame. One encoder failure reconnects; two within a minute switch new streams to PNG.
- `node/android/grpc.cjs`: adds the `ImageTransport` field and an `unbounded` mode for viewer streams that requires an abort signal (no 30-second restart).
- `node/android/devices.cjs`: launches with `-gpu host` and retries once with `-gpu auto` if the emulator exits during startup; reports the selected renderer from the emulator log. Before launch it starts adb and copies the user's adb key into the private emulator home, because on a Mac without `~/.android/adbkey` the emulator generated its own key and the device stayed `unauthorized`.
- `node/platform-stage.js`: Apple TV and Vision Pro use H.264 when WebCodecs exists, MJPEG otherwise or after two decoder failures, and drop to 2 fps while hidden.
