# Cindy Ping

Give the cat a poke to ping Cindy. What you’re looking at and what you want done go along with it, and Cindy takes it from there. Currently supports macOS 14+ only.

A configurable desktop emote wheel for **macOS 14+ (Apple Silicon and Intel)** and **Cindy 0.1.120 or later**. Hold a shortcut, point at an emote, and release. Start with display-only reactions, then connect individual emotes to projects, conversations or companions. Windows and Linux are not supported. There are no third-party runtime dependencies.

## Use

Import the generated `.cindy` package into Cindy and enable Cindy Ping in plugin details. Settings apply immediately. Record a modifier, single key or combination; the default is `Command + G`. **Press to open the wheel at the pointer, hold while moving, and release the shortcut to send and close. No click or drag is needed.** The centre, Escape, right-click or moving beyond 240 points cancels. Selection is retained just outside the visible wheel. Other key combinations cancel the current wheel; a letter/digit single-key binding reserves that character while enabled.

Recording temporarily suspends wheel input. Escape, loss of focus or timeout cancels recording and restores it. Use the selected key to apply it immediately. Accessibility is required for the input hook, including display-only use. This plugin only checks existing access and never requests separate system authorization. After updating Cindy to a build with permission sharing, disable and re-enable the plugin in Cindy, then refresh its status.

Configure at least four emotes with no fixed maximum, using emoji or local PNG/JPEG/GIF/WebP images. Click a wheel slice to configure it, drag to reorder, and use its Pin/delete controls. Pin preserves its angle. Use the centre + and move to choose an insertion position. Local images are referenced, not copied: keep the original files. Animated files use the image frame decoded by macOS; animation playback is not guaranteed. Each emote appears immediately and owns its lifetime. Sending captures the original window immediately; delivery waits two seconds after the last trigger and any required input. Settings follow Cindy's language; Japanese and Korean settings use the documented English fallback.

Actions:

- **Display only**: no capture, model call, task or message. Also discards the previous pending action.
- **Create a conversation**: choose a project, model, reasoning effort, supported Fast option and permissions per emote, or retain Cindy defaults. Permissions offer Ask, Auto-review and Full access. Explicit permissions require `tasks.capabilities().createPermissionMode`; unsupported hosts show an update message and never silently fall back.
- **Add context to a task**: select any available local ordinary task each time, or bind a fixed task. The recipient keeps its model, permissions and directory.
- **Send to a companion**: choose each time or bind a fixed active companion; delivery resolves the canonical conversation and preserves its settings.

The editor groups actions into Display and Send a message. Display also cancels the previous pending action during its 2-second wait, explained by a short tip. Completed effects are not rolled back. The wheel keeps at least four emotes: clicking Delete at that limit explains why; above four, deletion works directly. Destination presets group new conversations, existing conversations and companions, each with a fixed destination or per-trigger selection. Dynamic menu options state “Recently active · up to 3 · choose one” before selection; they never mean sending to all three. Fixed targets are chosen in settings with name/directory filtering. A stable `{kind,id}` is stored and resolved on each trigger; unavailable targets are never replaced automatically.

Each sending emote chooses **Preset** or **Type each time**. Preset is the default for existing configurations and uses the saved instructions without opening an input bar. Only Type each time opens a compact, single-line input bar after capture. A new input bar starts empty. It stays open after the emote fades; Enter or the visible Send button confirms, and Esc cancels. Losing keyboard focus also closes the bar and cancels the unsent action, including during IME composition. Consecutive input-mode emotes reuse that bar and its unfinished text without reopening or moving it; only the last trigger's action and captured window remain active. While that capture is pending, sending is disabled. IME composition and the cursor are preserved. Sending or cancelling clears the text; it is never saved or carried into a newly opened bar. Display-only and preset emotes close any previous input bar and never open one themselves.

While the current input bar remains open and its action has not been replaced, the captured screenshot stays in memory without an input timeout. Sending uses this original snapshot rather than taking another screenshot. Completion, cancellation (including loss of focus), replacement or stopping the plugin releases it.

Dynamic destinations reveal only the three most recently active candidates at most, with the same rule for projects, conversations and companions. There is no full-list mode or wheel pagination. Legacy `pick` settings normalize to `recent` without changing fixed bindings. Cindy supplies the activity order; candidates are queried and frozen for each wheel opening, never reordered in an open wheel or chosen automatically. Fixed and local actions do not expand. Releasing without a required destination, before loading finishes or with no available targets sends nothing. The wheel is about 228 points across, shows only emotes at the first level and keeps the opening pointer as its centre.

Only new conversations show model and permission controls. The searchable picker groups models by Claude Code, Codex or Pi and identifies the provider; reasoning and Fast controls live in a keyboard-accessible side flyout. Overflowing model and destination lists have visible scrollbars. Hidden models are collapsed initially, while the current selection stays visible. Selecting the current model again preserves valid tuning; reselecting a model with unsupported settings restores its current defaults. Models come from Cindy’s available catalog, and unavailable choices are retained for explicit reselection rather than silently replaced. Existing conversations and companions retain their own model, directory and permissions; Ping no longer calls `setModel` on existing tasks. The manifest retains `agent.tasks:true`, `agent.targets:true` and `showTaskPreferences:false`. Permission checks, delivery, message provenance and chat presentation use Cindy’s public APIs and standard flows; no plugin-specific permission ceiling or private IPC is added.

For task and companion destinations, each emote also chooses **Queue** (the default) or **Insert now**. Queue waits until the recipient is ready; Insert now adds context to its running turn without stopping it. If insertion is unavailable, Cindy queues the input and the status shows the actual delivery mode. When idle, normal queued input can start immediately. Screening rejection never retries through the queue; an uncertain insertion stays paused for inspection rather than sending another copy. Existing emotes without this setting retain queue behavior. Legacy owned-task bindings keep their original API and queue behavior without applying their old model overrides; select a destination mode to use the new delivery setting.

The host API is `cindy.targets.list/resolve/send/cancel`. Both `agent.tasks:true` and the independent `agent.targets:true` are declared; Cindy enforces its destination capability checks independently of owned-task access. The plugin checks the actual API and image capabilities before use. Unsupported clients stop with a clear message rather than using private IPC or changing receivers. Existing emotes without `target` keep their owned-task API, task bindings and directory behavior. Model and permission overrides apply only to new conversations. No migration silently changes the destination.

New installations start with Help me out, Verify, Find ideas, and a dedicated Undo cat emote. All four display only; Undo retains its own cat image. Every display-only emote cancels the previous pending action. Legacy undo settings normalize to display-only without changing images, names or positions. Eleven cat images are available. The library contains no prompt templates, and adding an emote or changing its action never fills instructions automatically. Write your own preset instructions, or select Type each time to enter them after triggering. Image replacement preserves your settings. Updates convert untouched factory task prompts to display-only and replace the fourth untouched factory slot with Undo, retaining the shortcut and positions. User-authored instructions, fixed destinations, explicit models for new conversations and custom wheels are preserved. Both built-in and custom images start as display-only when added.

Each trigger pops the emote immediately, settles through a 460ms spring with two expanding ripples, and fades after 2 seconds. The system Reduce Motion preference skips the spring and ripples. Delivery waits until two seconds after the last trigger, target selection and any required input are complete, and can incur model costs. If task access is denied, change the action to display-only.

## Capture and cancellation

Confirming a sending emote immediately starts bounded accessibility reading and optional capture of the original window, before the two-second wait or per-use input. The input bar opens only after capture; delivery reuses that snapshot rather than capturing again after the user switches pages. Capture is asynchronous, not a historical recording of the exact trigger instant. The helper never reads the clipboard or records continuously. Permissions are checked without prompting; unchecked is distinct from denied. Client change #6029 launches macOS Node workers with `disclaim: false`, allowing their child processes to use Cindy's TCC responsibility. The plugin starts its bundled helper directly from that worker and provides no separate permission-request buttons or native permission-request calls. If access is unavailable, it reports the missing capability instead of requesting authorization. Native compilation alone does not verify system-permission access in an installed client. Either material can be missing, with the reason recorded. Password fields are skipped by the accessibility reader; screenshots can still contain anything visible in the chosen window.

The original window is identified immediately **after** the emote is displayed. ScreenCaptureKit captures that exact window, excluding the emote, wheel and input bar. If the window is closed, it does not switch to another app or capture the whole desktop. Text selection must belong to the same target window; nearby text is bounded rather than a complete browser DOM scrape.

Screenshots are sent as image attachments through Cindy's existing managed-media and message pipeline, for both new destinations and legacy owned-task bindings. The message body contains only your instructions. Window text, source-window details, capture time, missing fields and cursor position are passed separately as `context`, which Cindy shows as attached reference material and gives to the Agent. New conversations use Cindy's automatic titles based on the instructions and material, instead of a fixed emote name; existing conversations and companions keep their titles. The client must advertise `tasks.capabilities().messageContext`; creating conversations also requires `autoTitle`. Missing capabilities stop delivery with an update message, without mixing material back into the body or reverting to a fixed title. No capture folder, `context.json`, temporary screenshot path or separate media-deposit permission is needed. The client must advertise `tasks.capabilities().messageAttachments` with image support; otherwise screenshot delivery stops with an explicit update message. Images are visible in message history and included in model input for queue and same-turn delivery. No screen contents are written to plugin KV or diagnostic logs. Unadopted images follow Cindy's existing media reclamation rules.

Every trigger replaces one global pending action. Only one capture runs at a time, with at most the latest trigger waiting; intermediate requests and stale results are discarded. One current in-memory snapshot is retained until replacement, cancellation or completion. No capture files or screenshot history are created. Esc during the wait or input cancels the unsent action while leaving the displayed emote. If the wheel has been reopened, Esc closes it and also cancels the previous waiting send; releasing the shortcut afterward cannot send it. It does not recall a message whose delivery has started. Legacy inputs are cancelled by their own `runId`. New destination inputs withdraw only their host-generated queued input; an already running turn is not forcibly stopped. This includes late receipts; the plugin never stops an entire task or someone else's input. Completed side effects cannot be undone. If cancellation or dispatch is unconfirmed, automatic delivery pauses and requires inspection in Cindy; no automatic resend or new request key bypasses an ambiguous result. Restart never replays old work.

## Development and package

The JavaScript and `node/*.cjs` files are handwritten plugin source, not a vendored bundle. No third-party runtime libraries are included.

Run `node scripts/build.mjs` on macOS with Xcode Command Line Tools. It compiles arm64 and x86_64 helpers targeting macOS 14 and applies a local ad-hoc signature. The bundled helper is ad-hoc signed, not separately notarized. It runs as a child of Cindy’s Node worker, without a separate app launch. Source is in `native/EmoteHelper.swift`; the installed package does not need Swift or Node installed separately.

`npm run check` checks JavaScript syntax. `node scripts/stage.mjs` stages only runtime files under `build/package`. Use Cindy `ghost_forge_pack` on that directory. Packing does not install or publish the plugin.

Native helper and shortcuts exit when the worker's input closes, or when Cindy stops the plugin. Disable the plugin in Cindy to release input hooks while retaining configuration. The official repository packages the committed plugin directory with its root license and trademark notices.

Reference: [Cindy](https://github.com/makecindy/cindy), [ScreenCaptureKit window filter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(desktopindependentwindow:)). [lolPing](https://github.com/darrenprx/lolPing) inspired the interaction; no code or League of Legends assets are copied.

Run `node --test .tests/cindy-ping.test.mjs` from the repository root for isolated scheduler, configuration and delivery regressions. These checks do not launch Cindy or send real messages. Native compilation and mocked checks do not replace real-device verification.

The icon and eleven cat emotes are original illustrations generated for this plugin, not bundled emoji fonts or copied game assets. The emotes use lossless WebP at their original 1254 × 1254 resolution; all decoded RGBA pixels match the earlier PNG assets. Existing built-in PNG references are mapped to the corresponding WebP without changing instructions or destinations. Custom image paths are unchanged. No image decoder is bundled; Cindy and macOS decode the assets.

## Agent configuration

Use `get_config` for the full configuration and revision, and `list_targets`/`list_models` for exact identifiers. Submit only the requested edits within the complete config through `configure({revision, config})`. The tool and settings page share validation, revisions and a serial queue. A stale settings page cannot overwrite a newer Agent edit. Saving never displays an emote, captures content or sends a message. A stale snapshot returns `STALE_REVISION`; read again before editing. Per-emote actions, destinations, images, instructions, promptMode, models, delivery, angles/Pin and the shortcut are configurable. promptMode defaults to preset; input opens a blank single-line per-use prompt and ignores the saved prompt. Configuration retains the saved prompt for preset mode; submitted per-use text is never written back. Preserve unrelated fields; new entries should be display-only with an empty prompt, at least four entries and unchanged pinned angles.

The plugin omits `command`, so it has no standalone chat entry. Agents can still discover its tools and configure it from an ordinary conversation.
